# Wagomu: the other Tegaki recognizer

Date: 2026-11-08
Status: research notes

## 1. What Wagomu is

Wagomu is the second handwriting recognition engine shipped by the Tegaki
project. It is described by its README as a “simple handwriting recognition
engine based on DTW” (dynamic time warping). It is not a dataset; it is a
recognizer plus a set of models trained from the same kind of online stroke
data.

- Project: <https://tegaki.github.io/>
- Engine release: `tegaki-wagomu-0.3.tar.gz`
- Recognition models: Japanese (full, joyo, kyoiku) and Simplified Chinese.
- There is no Traditional Chinese Wagomu model in the 0.3 release.

## 2. Model facts

| Asset | Language | Size |
|---|---|---:|
| `handwriting-zh_CN.model` | Simplified Chinese | 7.9 MB |
| `handwriting-ja.model` | Japanese | 8.4 MB (2.2 MB archive) |
| Japanese joyo / kyoiku models | Japanese subsets | 0.6 MB / 0.3 MB archives |

The Simplified Chinese metadata:

```text
name = Simplified Chinese
shortname = 中
language = zh_CN
downsample_threshold = 50
window_size = 3
```

The model is much smaller than the Zinnia model (7.9 MB vs 26.8 MB). That is
because Wagomu's DTW model stores prototypes rather than a linear SVM per
class.

## 3. Licenses

- Engine source: GPL-2.0-or-later. The source header says “version 2 or (at your
  option) any later version”; this is compatible with GPL-3.0-or-later for a
  combined work.
- Model archive: the model data ships with an LGPL-2.1 `COPYING` file, matching
  the Zinnia/Tomoe model licensing.
- The Wagomu engine is not part of the Zinnia model; do not assume the model
  license covers the engine.

## 4. Why it is interesting

- It is a **different algorithm** from Zinnia (DTW vs linear SVM), so its errors
  may be complementary. A small ensemble or reranker could improve top-k.
- The model is 3–7× smaller than Zinnia, which is attractive for a data package.
- It covers Simplified Chinese and Japanese; no Traditional Chinese model.

## 5. Why it is not a drop-in replacement

- The engine is Python 2.4-era code with SWIG bindings and GLib dependencies.
  `fcitx5-ink` is C++/Rust and should not gain a Python 2 runtime.
- There is no Traditional Chinese model.
- DTW recognition cost grows with prototypes/classes; speed must be measured on
  a panel workload.
- The release is 0.3 (published 2016) and is not actively maintained.

## 6. Possible uses

1. **Evaluation oracle**: run Wagomu and Zinnia on the same held-out samples and
   compare top-1/top-5. This answers whether an ensemble is worth pursuing.
2. **Reranker**: use Wagomu's distance scores as an additional feature for a
   small candidate reranker.
3. **Prototype port**: if the accuracy is clearly complementary, port the DTW
   scorer to C++/Rust; do not ship the Python 2 engine.

## 7. Experiment

Prerequisites:

- a small C++/SWIG build of Wagomu (or a Python 2 container) for offline
  evaluation only;
- the same normalized online stroke samples used by the Zinnia evaluation;
- the Wagomu `handwriting-zh_CN` and `handwriting-ja` models.

Measure:

- top-1/top-5/top-12 on the shared evaluation set;
- complementarity: how often Wagomu's top-1 is in Zinnia's top-5 and vice versa;
- CPU latency and memory.

Stop rule: if the union of Zinnia + Wagomu top-5 does not improve over Zinnia
top-5 by at least 2–3 points, do not integrate it.
